# Distill Lessons

Distilling too often bloats the guidelines files, and therefore the context window of every future session.

1. **Qualify the Lesson**: Review the conversation and recent work for what it taught, then require both tests of each candidate: the lesson would have changed how this work was done, and it generalizes beyond this task. A lesson that fails either test is not worth recording.
2. **Locate the Target**: Detect where the project's durable guidance already lives, in priority order: its agent instructions file, then its contributor documentation, then a documentation directory. Propose one target rather than assuming a filename.
3. **Draft the Edit**: Write the lesson as a concise, generic principle folded into the existing section that covers the topic, not appended as a new one. Say each thing once, and prune restated or stale guidance when the file has grown.
4. **Stop for Approval**: Present the proposed target and the exact edit, then wait for approval before writing to any file. Once approved, apply the edit as presented and write nothing else.
