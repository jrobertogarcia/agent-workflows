# Orchestrate: Dispatch

Read this before the first dispatch in a phase, and again after any context summary. It extends the orchestrate `SKILL.md`, the core, whose terms, paths, Halt, and BLOCKED rules apply here.

## Dispatch

Send each step as one prompt, built from the template, to the agent its table row's Agent column names (`light`: `orchestrate-step-light`; `session`: `orchestrate-step`), or for any other step defined outside the table and not a variant, its `Agent:` statement, as a fresh subagent with no conversation history (never a fork of this context, `review-branch` too), working in this checkout, not an isolated copy or worktree. Run one step at a time: dispatch nothing else and change nothing until that step's final report has arrived, whether the host returns it from the call or delivers it later as a message. A launch acknowledgement or a running status is not a report. A variant runs on its base step's agent: `A1-fix` and `A1f` as `A1`, `A2f` as `A2`. `session` is for steps whose wrong answer no later step catches; `light` is for steps whose output a later step or the human checks; `replies` fits `light` but stays on `session` until measured (#78).

- **Before every step**: `git status --porcelain --untracked-files=all` is empty, else halt listing the dirty paths; every worker discards uncommitted changes.
- **Committing steps**: a step marked ✎ may commit. After it returns, read `git rev-parse HEAD` yourself (a reported SHA is only a cross-check) and write `branch_tip_sha` = `HEAD`; when the step's result sets `BLOCKED`, this write is folded into the BLOCKED write.
- **After every step** except `branch`: `git branch --show-current` is unchanged, `git status --porcelain --untracked-files=all` is empty, after an unmarked step `HEAD` equals `branch_tip_sha`, and after a ✎ step `branch_tip_sha` is an ancestor of `HEAD`. Otherwise halt with the report.
- **Result**: read the reply's last line, `Result: <token>`; the token must equal one of the step's Tokens or `STOPPED` exactly (case-sensitive, verbatim, no suffix). A missing line, an unrecognized token, a crash, network or rate-limit error is transient: re-run the step once unchanged, not counted, writing no tip until the re-run returns; a second transient on the same step sets `BLOCKED` (except `release` and `resolve`, per Release and `<resolve>`). `STOPPED` is valid from every step and sets `BLOCKED` with the report (except `release` and `resolve`, per Release and `<resolve>`); it is never transient. If the worker may still be running (a timeout or lost connection), do not re-run: halt and report; re-invoke once it has finished.
- If you cannot dispatch a fresh `orchestrate-step` or `orchestrate-step-light` subagent, halt: 'orchestrate needs a host that can run the `orchestrate-step` and `orchestrate-step-light` agents as subagents; install them with `setup.py link`.'

Template (fill every `<...>`; omit the branch clause before the branch exists, and for close-out steps per `<close-out>`; `<report path>` is per Reports). `<guidelines>` is `AGENTS.md` if it exists at the worktree root, else `CLAUDE.md` if it exists there, else omit the `Repo guidelines:` line. `<skill reference>` is the step's skill referenced per Paths, and <`create-commit` reference>, here and in the table, is `create-commit` referenced per Paths; for `A1` it is "the approved plan at <plan.md path>, committing per <`create-commit` reference>", and for `A2` "<`validate-commit` reference>, then <`prepare-handover` reference> for the handover".


## Reports

- **Report path**: `S/<branch>/reports/<file>` once `S/<branch>/` exists; before that, `S/stacks/<name>/reports/<file>`, or `<provisional>/reports/<file>` during Start per `<start>`.
- **File name**: `<step_id>.md`; for `resolve`, `resolve-<purpose>.md`, with purpose `story`, `story-rerun`, `plan`, `triage`, or `close-out`.
- **Close-out steps** (`inventory`, `tickets`, and `resolve` for `close-out`) report to `S/stacks/<name>/reports/` and are defined in `<close-out>`.
- **Before each dispatch**: `mkdir -p` the reports directory and `<reports>/prev/`, then move an existing report file of the step to `<reports>/prev/<file stem>-<UTC time>.md`, so earlier rounds' `## Out of scope` lines survive for close-out; for `context`, also `rm -f` `context.md`.
- **Transient results**: besides the Result rule on the reply's last line, a step's result is transient when its report file is missing; after `context`, when `context.md` is missing; after `plan`, when `plan.md` is missing or not newer (`-nt`) than `state.json` and every other input file the dispatch named.
- **Held**: a report is held while its file exists.
- **Fix Input**: build each fix-pass input with `{ ...; } > "$tmp" && mv -f "$tmp" <dest>`, printing nothing (an inner pass reads the current `fix-input.md` into `$tmp` first). Its sources:
  - a step's report as the input: that report file;
  - **selection block** (auto-fix, `fix <n>, <m>`): the line `Selected: findings <n>, <m>` (or `comments`), then `## Source <path>`, then that file (`review.md` or `comments.md`) concatenated, a frozen copy, since Findings replaces `review.md` on the next round;
  - **Small from text**: the human's text;
  - **inner pass**: the current `fix-input.md`, `## <step id>`, then that step's fix-input source.
- **Item lookups**: `fix <n>, <m>` and the gate-time tier lookups use `grep`, never a read of the file, matching the full line shape: `grep -m1 -E '^Finding <n>: (Critical|Important|Suggestion|Nitpick) (New|carried)$'`, the first match, and `grep -E '^Item <n>: (fix|defer|discuss|already answered) Tier: '`, the last match.
